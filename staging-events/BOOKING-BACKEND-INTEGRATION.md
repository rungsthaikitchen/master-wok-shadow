# Private booking-store backend integration

Default-off, synthetic staging only. event_booking_transport.py adds fixed parameterized create/apply calls against the new production-shaped private booking store, with the existing restricted writer login and pinned verify-full TLS. No general SQL, public.orders writes, notifications or provider calls. Signed aliases are resolved to UUID rows inside the fixed SQL statement; a customer cannot supply a replacement UUID through the response body.

The existing private operator HTTP server can explicitly install /staging/create-booking with a creation transport. Without that argument the route is absent. Signed response and admin offer routes reuse the existing validated command boundary. The Flask review module can select this transport only with MASTER_WOK_BACKEND_EVENT_STORE=booking_rows under all previous exact staging gates; default remains the earlier synthetic store. The Flask route itself has not been deployed. Existing admin confirm helper and this store have different explicit-target contracts; this trial covers creation, offers and proposal responses, not the legacy admin confirmation mapping.

booking-store-role.sql gives the existing staging writer SELECT on three new private tables, INSERT on the creation/basket/receipt columns, UPDATE only on status/proposed_time/confirmed_time/current_proposal_event_id, and EXECUTE on three SECURITY INVOKER functions. RLS limits reads and writes to enabled synthetic streams. No DELETE, item UPDATE, original preferred-time UPDATE, stream enablement, public schema write or credential changes are included. Catalog assertions in booking-role-acceptance.sql passed. A management-session SET ROLE rehearsal was refused; no admin membership was added. Actual login execution is tested only by the separately deployed trial, not inferred from catalog checks.
